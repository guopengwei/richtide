# UZI production-reuse audit

## Decision

Do **not** import UZI as a production runtime or preserve its 22-dimension/66-persona product model. Treat the snapshot as a read-only methodology quarry.

- **No material seam is safe for direct production reuse.** The strongest parts are candidates to **adapt**: ticker normalization, explicit missing-value semantics, source/fallback registries, bounded concurrent collection, deterministic DCF/comps calculations, currency-normalized peer comparison, methodology logs, and report patterns that disclose assumptions, disagreement, data gaps, and freshness.
- **Rewrite** every RichTide canonical contract, evidence record, provider adapter, calculation wrapper, quality gate, orchestration mechanism, and renderer around the approved five-module schemas and Cloudflare operating model.
- **Exclude** the investor-persona jury, overall/alpha scores, buy/sell/position guidance, entertainment-oriented report language, local public tunnel, local file cache as system of record, unlicensed scraping paths, and the existing pseudo-Wyckoff stage. UZI contains no Al Brooks engine and no governed Wyckoff state machine.

This boundary preserves the useful analytical ideas without inheriting an unauthenticated single-user CLI, weak revision provenance, source-licensing uncertainty, non-canonical schemas, inferred or fabricated evidence, or advice-like outputs.

## Scope and classification meanings

The approved RichTide baseline defines three Core modules—Fundamentals & Business Quality, Valuation & Scenarios, and Catalysts & Risks—and two Pro research-beta modules—Wyckoff Market Structure and Al Brooks Price Action ([spec lines 10–17](../../../UZI_Cloudflare_Retail_Investor_Platform_Simplified_Design_Spec_v3.md#L10-L17), [module table lines 37–47](../../../UZI_Cloudflare_Retail_Investor_Platform_Simplified_Design_Spec_v3.md#L37-L47)). The audit uses:

- **Reuse**: copy substantially as-is into a production path.
- **Adapt**: preserve an algorithm, mapping, test vector, or interaction concept, but port it behind new contracts and governance.
- **Rewrite**: use the source only to enumerate requirements or failure cases; implement independently.
- **Exclude**: intentionally keep out of the governed product.

## Snapshot identity and license

- The local directory is a source archive, not a Git worktree: it has no `.git` metadata, so there is no locally provable commit SHA, tag signature, or upstream-to-local chain of custody. The auditable snapshot identity is therefore the file content and declared version, not a VCS revision.
- `SKILL.md`, `package.json`, and the Claude plugin manifest declare **3.9.4** ([SKILL lines 1–9](../../../Reference_Only/UZI-Skill-main/SKILL.md#L1-L9), [package lines 1–12](../../../Reference_Only/UZI-Skill-main/package.json#L1-L12), [plugin manifest lines 1–11](../../../Reference_Only/UZI-Skill-main/.claude-plugin/plugin.json#L1-L11)). Release notes identify v3.9.4 dated 2026-08-08 and claim 685 passing tests ([release notes lines 1–25](../../../Reference_Only/UZI-Skill-main/RELEASE-NOTES.md#L1-L25)). This audit did not execute the suite because doing so could create cache/report files inside the read-only reference tree.
- Revision metadata is internally stale: `.version-bump.json` still says **3.9.1**, even though it lists the manifests it expects to align ([version metadata lines 1–25](../../../Reference_Only/UZI-Skill-main/.version-bump.json#L1-L25)). RichTide must not use the declared version as a provenance identifier.
- The repository license is MIT, copyright 2026 Float Future. It permits use, modification, distribution, sublicensing, and sale provided the copyright and permission notice are retained, and disclaims warranty ([LICENSE lines 1–20](../../../Reference_Only/UZI-Skill-main/LICENSE#L1-L20)).
- MIT covers the software snapshot; it does **not** grant commercial rights to upstream market data, scraped content, investor names/likenesses/quotes, or every adapted upstream work. The code explicitly says multiple financial methods were adapted from `anthropics/financial-services-plugins` ([fin_models lines 1–19](../../../Reference_Only/UZI-Skill-main/skills/deep-analysis/scripts/lib/fin_models.py#L1-L19), [research_workflow lines 1–16](../../../Reference_Only/UZI-Skill-main/skills/deep-analysis/scripts/lib/research_workflow.py#L1-L16)). ## Operational and security risk register

1. **No source revision chain.** Version 3.9.4 is declared but no commit is locally provable, and `.version-bump.json` is stale. Any extraction must record exact file hashes and a reviewed upstream commit/tag before code enters a production branch.
2. **Data rights are the primary blocker.** “Free/no key” and technical accessibility do not establish commercial ingestion, storage, redistribution, derived-data, or display rights. Scraper endpoints, search snippets, and personal Tushare/MX credentials must not become RichTide production dependencies without market-specific approval.
3. **Evidence is too coarse.** A dimension-level source label cannot prove which statement, date, period, unit, or field supported a claim. Fallback merges preserve only a compact marker, not claim-level lineage.
4. **Silent semantic degradation.** Broad exception swallowing, “never raises” fetchers, empty results, optional-only specs, automatic legacy fallback, and CLI warning downgrades can still yield a polished report.
5. **Non-point-in-time behavior.** `datetime.now()`, current provider responses, TTL cache reuse, guessed events, and no as-of revision make replay and corrections unreliable. This is fatal for technical calibration and “what changed.”
6. **Calculation assumptions are not governed.** A-share constants, approximate FCF, absent-debt tolerance, generic company treatment, and verdict thresholds can produce precise-looking but inappropriate outputs.
7. **Single-user filesystem architecture.** Relative caches/reports, process-global environment, local browser state, and a bearer public tunnel have no tenant, entitlement, audit, deletion, or concurrency guarantees.
8. **Renderer injection exposure.** Main report interpolation is not uniformly escaped. API titles, search snippets, and agent prose are untrusted content in a future multi-tenant product.
9. **Supply-chain drift.** Lower-bound-only Python dependencies, runtime installation, optional undeclared packages, duplicate requirements, browser binaries, and third-party copied/adapted code prevent reproducible qualification.
10. **Product-boundary risk.** Persona jury, “ideal buy price,” target zones, position sizing, and Hold/Add/Trim/Exit language could be interpreted as advice and conflict with RichTide’s approved structured research workspace.

## Approved extraction boundary

Before any UZI-derived production implementation begins:

1. Freeze a reviewed upstream commit/tag and generate a full file manifest, SBOM, license/notice bundle, and source-content/data-rights review.
2. Create independent RichTide types for Instrument, Evidence Record, Observed Fact, Calculation Run, Module Result, Data Gap, Parameter Set, Calibration Version, Artifact, and Correction. Do not import `raw_data.json`, `dimensions.json`, `panel.json`, or `synthesis.json` as canonical contracts.
3. Port only selected pure concepts behind those types: ticker test cases, missing-value semantics, peer currency normalization, DCF/comps formula test vectors, methodology-lineage requirements, bounded DAG behavior, and UX disclosure patterns.
4. Require licensed provider adapters to emit field-level evidence with source document, event/observed/fetched/as-of timestamps, raw hash, unit/currency/period, and rights policy. A fallback is a new evidence path, never a hidden merge.
5. Reimplement all quality gates from the five module contracts. No runtime mode may downgrade a missing critical requirement into publishable “partial” content without a typed, customer-visible omission and policy-authorized partial artifact.
6. Build Wyckoff and Brooks independently as versioned research-beta engines with point-in-time replay, frozen definitions, calibration, hard negatives, no-look-ahead tests, and explicit “unknown/not assessed” states.
7. Exclude every persona, quote/likeness asset, recommendation label, buy zone, position sizing rule, “battle plan,” local tunnel, and legacy report renderer from the extraction set.

## Bottom line

UZI provides useful analytical vocabulary, edge cases, deterministic calculation examples, and a rich catalog of failure lessons. It does **not** provide a production-ready engine for any of the five RichTide modules. The safe decision is **adapt concepts and test vectors; rewrite governed code and contracts; exclude the legacy product surface and advice/persona machinery**.
